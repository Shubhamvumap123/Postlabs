## 2024-05-18 - XSS Vulnerability in Custom Scroll Animation Hook
**Vulnerability:** A DOM-based Cross-Site Scripting (XSS) vulnerability was found in `useScrollAnimations.tsx` where text was dynamically split and directly assigned using `element.innerHTML`.
**Learning:** `element.innerHTML` assignment bypasses React's default XSS escaping mechanism. While it was extracting text from `innerText`, any previously injected scripts or user-controlled content in the DOM could be parsed and executed when re-assigned using `innerHTML`. This issue bypasses the React DOM and opens up XSS vectors through animation effects.
**Prevention:** Avoid `element.innerHTML` assignment for manipulating DOM nodes inside custom React hooks. Use native DOM API `document.createElement`, set properties safely with `.textContent`, and `element.appendChild()`, or structure the markup safely using React state and JSX.
## 2026-09-06 - LocalStorage Array Structural Validation\n**Vulnerability:** Application lacked structural validation of `localStorage` data (e.g., checking if it's an Array), leading to potential runtime `TypeError` crashes during subsequent array operations if corrupted or intentionally malicious data was loaded.\n**Learning:** Relying purely on `JSON.parse()` without structural validation for untrusted data like `localStorage` creates a Denial of Service (DoS) vector on the client side, as non-array data types (like plain objects or booleans) will crash the application when methods like `.map()` or `.filter()` are called.\n**Prevention:** Always validate the structure and type of data retrieved from `localStorage` (e.g., using `Array.isArray(parsed)`) before performing operations on it, and implement safe fallbacks (like returning an empty array).
## 2026-09-12 - Prevent hardcoded JWT fallback secrets
**Vulnerability:** JWT authentication mechanisms were falling back to hardcoded strings like 'secret' or 'fallback_secret' if the JWT_SECRET environment variable was missing.
**Learning:** This fallback meant that if a production environment accidentally missed the secret configuration, the app would transparently use a weak, known secret, exposing tokens to forgery without failing loudly.
**Prevention:** Never use OR (||) fallback values for critical secrets. Instead, explicitly check if the secret is defined and throw an error or crash the process to fail securely.

## 2026-10-25 - Mass Assignment in Job Controllers
**Vulnerability:** req.body was passed directly to Mongoose update operations, allowing users to overwrite protected fields like user, userId, and _id.
**Learning:** Due to schema discrepancies between .js and .ts files, using an explicit allowlist was problematic. The solution was to clone the request body and explicitly delete restricted fields before the update operation.
**Prevention:** Always sanitize req.body before passing it to database update methods by cloning the body and deleting restricted fields.
